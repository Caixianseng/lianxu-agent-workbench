# Agent Workbench MVP contract

Local Node >=20.18 application. The workbench core has no third-party npm dependencies; the optional official Qoder CLI is installed separately under data/runtime/qoder. Windows native file selection uses the local .NET Framework runtime/compiler. Chinese UI. API and local CLI supported. Bind loopback. JSON persisted in data/state.json. No arbitrary generated code execution.

## HTTP API

- POST /api/runs/:id/chat -> 202 run. Body: {message}, nonempty and at most 6000 characters. Only awaiting_approval accepts a message. The lead asynchronously returns {reply,assignments:[{taskId,agentId}]}; validate the whole batch against the run's immutable Agent snapshots and eligibility before changing suggestions. Empty assignments is clarification. The response does not approve or execute tasks. Messages are persisted as {id,role,content,time,assignments?}; chatBusy, chatError and per-task routingRevision let the browser show progress and update only affected choices. Calls use the existing budget and global model-call lock. Cancelled or restarted chat cannot apply a late result. Runs without chat fields remain compatible.
- Planning output tasks may include optional preferredAgentId (a known eligible Agent ID), preserving explicit user routing requirements. Optional plan.reply describes the proposal or asks the user to clarify. The selected lead remains unchanged.

- GET /api/state -> {agents,runs,cliProfiles}; cliProfiles = [{id,name,available,detail}]. API agent secrets are environment-variable names only.
- POST /api/agents -> agent. Body: {name,provider,model,tier,skills,baseUrl?,apiKeyEnv?,cliProfile?,cliSelectionId?}. provider: demo | openai-compatible | cli. tier: 1 economical, 2 balanced, 3 powerful. skills: string[]. For CLI, supply either a server-issued cliSelectionId or an existing cliProfile, never both; model must be present in that selection/profile's discovered model list. Raw executable paths, commands, args and profile definitions are rejected. Validate the Agent before registering the selected profile; only the user-confirmed addition step triggers persistence of the discovered fixed CLI configuration.
- POST /api/cli/pick-file -> {selectionId,path,kind,name,models,source,updatedAt?,warnings}, or {cancelled:true}. Body: {} only. Open the Windows native file dialog on the server's current interactive desktop, allowing selection of a supported CLI .exe, OpenCode.exe or Qoder Launcher.exe / Qoder.exe desktop entry point, or local model-manifest .json. Identify the adapter, locate its actual CLI when necessary, and load its catalog without persisting configuration. Codex/Claude/manifest catalogs use local reads; OpenCode/Qoder catalogs run only fixed CLI model-listing commands, never desktop executables or inference requests. Keep the original discovered profile server-side under an opaque selectionId valid for 30 minutes; do not accept file paths, commands or args from the browser. Cancellation creates no selection. Reject concurrent open-picker requests. Request cancellation terminates this invocation's picker process and aborts supported model-listing work. There are no directory-browsing or select-file HTTP endpoints.
- GET /api/cli/profiles/:id/models -> {models,source,updatedAt?,warnings,path,name}. Read model choices for an existing local CLI profile. An empty model list cannot be used to create a CLI Agent. Model selection is a dropdown populated by discovery, not a manually entered model ID.
- DELETE /api/agents/:id -> {ok:true}. Reject agents referenced by active runs.
- POST /api/runs -> run immediately in planning status. Body {goal,leadAgentId,maxCalls:40,concurrency:2,demoFailure:false}. Lead plans asynchronously.
- POST /api/runs/:id/approve -> run. Body {assignments:[{taskId,agentId}]}. Require exactly one eligible assignment per task; tier >= task.complexity and all required skills. Complexity 3 or high risk always assigned to lead. No run execution before confirmation.
- POST /api/runs/:id/cancel -> run.
- GET /api/runs/:id/export -> Markdown download.
- API errors {error:string}. Poll GET state every 1 second.

Agent: {id,name,provider,model,tier,skills,baseUrl,apiKeyEnv,cliProfile,configured:boolean}.
Run: {id,goal,leadAgentId,status,createdAt,updatedAt,maxCalls,concurrency,demoFailure,callsUsed,tasks,events,summary,error,question,agentSnapshots,messages,chatBusy,chatError,routingRevision}.
Run status: planning | awaiting_approval | running | completed | needs_attention | failed | cancelled | interrupted.
Task: {id,title,description,complexity:1|2|3,risk:low|medium|high,requiredSkills:string[],dependencies:string[],acceptance:string[],suggestedAgentId,preferredAgentId?,routingRevision?,agentId,status,attempts,output,review,error,routingReason}.
Task status: pending | running | reviewing | retrying | escalating | passed | needs_attention | blocked | cancelled.
Attempt: {agentId,phase,output,review,error,startedAt,finishedAt}. Event: {id,time,type,message,taskId?}.
review: {passed:boolean,feedback:string,criteria:[{criterion:string,passed:boolean,evidence:string}]}.
CLI model: {id:string,name:string,description?:string}. Model IDs are trimmed and limited to 160 characters. A discovered model is a candidate from the stated source, not proof of current account authorization.

## Provider module
`src/providers.mjs` exports `callAgent(agent, request, {signal}={}) -> Promise<{data,usage?}>`, `getCliProfiles() -> Promise<array>`, and optionally helper validation exports. request {phase:'plan'|'route'|'execute'|'review'|'synthesize',goal,leadAgentId?,task?,tasks?,output?,feedback?,dependencies?,agents?,message?,messages?,demoFailure?,attempt?}. data for plan = {reply?,tasks:[{id,title,description,complexity,risk,requiredSkills,dependencies,acceptance,preferredAgentId?}]}; route = {reply:string,assignments:[{taskId,agentId}]}; execute = {content:string}; review = review schema above; synthesize = {content:string}. Runtime validates output separately. Environment API keys never returned. CLI profile commands fixed by trusted server config (config/cli-profiles.json optional); no shell invocation, bounded output/time, AbortSignal. Demo deliberately fails first economical worker when demoFailure=true, reviewer catches it.

Built-in OpenCode/Qoder task profiles disable tools and parse their CLI-specific output through `opencode-jsonl` / `qoder-json`. Project calls follow the existing planning and assignment-confirmation flow; model discovery uses separate listing commands and cannot initiate a project. A CLI located through a Node bundle has a fixed `cliPrefix` prepended to task argv and model-listing argv. Desktop launchers and shell wrappers are not task executables.

## Local CLI discovery and registration

`src/native-picker.mjs` exports `pickNativeAgentFile({signal,timeoutMs=300000}={}) -> Promise<string|null>`. It launches the fixed bin/NativePicker.exe with shell:false and windowsHide:false because the user explicitly requested a visible GUI; the background compiler uses windowsHide:true. The WinExe writes UTF-8 JSON directly to its inherited stdout pipe without console initialization. Parse stdout JSON {path:absolute} to a path string or {cancelled:true} to null. Limit stdout to 16 KiB and stderr to 4 KiB; do not expose raw diagnostics. Cancellation/timeout kills only this invocation's child and cleans up listeners/timers after close or a bounded fallback.

If the binary is missing or older than scripts/NativePicker.cs, compile through Windows .NET Framework64/v4.0.30319/csc.exe, falling back to Framework/v4.0.30319/csc.exe, with fixed /target:winexe and System.Windows.Forms.dll, System.Web.Extensions.dll and System.Drawing.dll references. Serialize concurrent compilation, use fixed absolute source/output paths, and download no external packages. The C# helper owns a visible WinForms owner and Application.Run message loop. The server must run as the current logged-in Windows user on the interactive desktop (ordinary npm start), not inside a restricted development sandbox or Session 0 service. Unsupported platforms or unavailable desktop/compiler conditions must report an error; do not silently substitute a web file browser.

`src/cli-catalog.mjs` exports:

- `discoverCliFile(filePath,{signal}={}) -> {profile,kind,name,path,models,source,updatedAt?,warnings}`. Discover from an absolute path returned by the native system picker without persisting configuration. Read Codex/Claude/manifest catalogs locally; locate OpenCode/Qoder CLI and run only its fixed model-listing command. `profile` is internal server data and must not round-trip through the browser.
- `discoverProfileModels(profileId) -> {profileId,kind,name,path,available,models,source,updatedAt?,warnings}`. Refresh an existing profile's model choices from its declared source.
- `registerCliProfile(profile) -> storedProfile`. Accept only an untouched original profile produced by this catalog instance's discovery. Serialize writes and atomically replace config/cli-profiles.json while preserving other profiles and configuration metadata.

Native Codex/Claude/OpenCode/Qoder names select the shared fixed restricted argv from providers; unknown executables are not run to probe them. Recognized OpenCode/Qoder desktop names trigger CLI location instead of launching the selected desktop executable. Windows .cmd/.bat/.ps1 entries are unsupported as Agent execution targets. File-name recognition does not authenticate a publisher signature.

`src/cli-locations.mjs` exports synchronous `findLocalCli(kind,{env=process.env,selectedPath,root=repositoryRoot}={}) -> {command,prefix:[],desktop:boolean}|null`, for kind opencode or qoder. It performs only filesystem reads at fixed candidate locations, reads environment keys case-insensitively, and never recursively scans user data or runs programs. `desktop` records whether the selected entry point was a desktop application; `command` always identifies the actual CLI or Node executable.

- OpenCode.exe with an adjacent resources/app.asar is a desktop entry point. Check resources/opencode-cli.exe and resources/bin/opencode.exe, then PATH installation candidates including node_modules/opencode-ai/bin/opencode.exe. A direct OpenCode CLI without the desktop marker can be used as-is.
- Qoder Launcher.exe / Qoder.exe are desktop entry points. Check PATH qodercli.exe and fixed home locations such as .qoder/bin/qodercli/qodercli.exe and .local/bin/qodercli.exe. If absent, use root/data/runtime/qoder/node_modules/@qoder-ai/qodercli/bundle/qodercli.js with command=process.execPath and prefix=[entry]. Never return a desktop exe or .cmd/.bat/.ps1 shim as the command.

`src/cli-models.mjs` exports `readCliModels(kind,location,{env=process.env,signal}={})` and `parseModelListing(kind,output)`. Run only the supported fixed listing argv: OpenCode prefix + `models --pure`, Qoder prefix + `--list-models`. Use shell:false, windowsHide:true, a 30-second timeout, a 2 MiB output-buffer limit and AbortSignal. Listing is not an inference request. Parse explicit returned model IDs only; preserve empty results and useful warnings instead of fabricating a model list. Qoder's unauthenticated response yields models:[] and a login instruction; such a result cannot create an Agent.

Optionally install official `@qoder-ai/qodercli@1.1.77` under data/runtime/qoder. `npm run setup:qoder` installs/reinstalls that pinned project-local dependency. The user completes independent Qoder CLI authentication through `npm run login:qoder` or by opening scripts/login-qoder.cmd, then selects Qoder again to reload models. The desktop session does not establish CLI authentication. The login helper is user-operated and is not registered as an Agent command.

Codex discovery reads CODEX_HOME/models_cache.json (or the user's .codex directory), projects only visible model IDs/names/descriptions, reports the cache timestamp, and warns about freshness/account changes. No inference request is made. Claude discovery reads explicit local model settings and known model environment variables; it does not invent a complete account entitlement list. Missing or invalid catalogs produce empty choices and useful warnings.

Other programs require a trusted local JSON manifest containing {name,command,args,outputFormat,models,envAllowList?,timeoutMs?,cwd?}. `models` is a nonempty array of model ID strings or {id,name,description?} entries. `command` resolves to a native executable; a Node-based CLI may use node.exe with its JS entry point in fixed args. Prompts go through stdin, and {model} is the supported argument placeholder. Discovery does not register this configuration; user confirmation when adding the Agent triggers registration. No secret values may be included in envAllowList.
